3. Machine-Readable Output Specification

This document describes the structured outputs generated by the system and explains how each field satisfies the challenge requirements.

The system produces two primary machine-readable files:
outputs/story_analysis.jsonl — full detail for automation, dashboards, and internal tooling
outputs/story_summary.csv — compact, reviewer-friendly summary for triage
Both formats share consistent IDs and field names, allowing them to be joined and extended with feedback in later iterations.

3.1 Story Analysis JSONL — outputs/story_analysis.jsonl

Each line of the JSONL file is a complete record for one story.
Example structure
{
  "story_id": "S_012",
  "story_title": "The Lost Backpack",
  "grade_level": 3,
  "priority_score_final": 0.78,
  "needs_human_review": true,
  "flags": [
    {
      "issue_type": "Bullying",
      "severity": "medium",
      "priority": 0.50,
      "rubric_category": "Emotional Safety",
      "evidence_text": "They all laughed at him and called him names.",
      "start_char": 220,
      "end_char": 270,
      "rationale": "Scene portrays social exclusion and name-calling directed at a child.",
      "source – "llm", "heuristic", or "synthetic"
    }
  ],
  "skills": [
    {
      "skill_id": "SKILL-COMP-003",
      "skill_name": "Character Analysis",
      "support_level": "strong",
      "confidence_raw": 0.80,
      "confidence": 0.86,
      "similarity_score": 0.78,
      "evidence_text": "Sam wondered why his friend suddenly stopped talking to him.",
      "justification": "Student must infer character feelings from actions and inner thoughts."
    }
  ]
}

Story-Level Metadata
Field	Description
story_id	Unique identifier from stories.csv
story_title	Title of the story
grade_level	Intended grade (K = 0 → Grade 8 = 8)
priority_score_final	Final 0–1 priority score used for triage
needs_human_review	Boolean signal that story requires human check
Flags (Safety & Content Issues)

Each item in flags is a validated issue surfaced by heuristics, LLM, or synthetic logic.

Field	Description
issue_type	Category of issue (e.g., Bullying, Violence, Unsafe Behavior)
severity	"low", "medium", "high", or "critical"
priority	Per-flag 0–1 priority (severity-based) for UI ranking
rubric_category	Top-level rubric category (e.g., Emotional Safety, Cultural Sensitivity)
evidence_text	Exact substring from the story text
start_char, end_char	Character offsets of evidence span
rationale	Human-readable explanation of why this is an issue
source	"llm", "synthetic" (forced review), or "heuristic" (if later added)
Requirement Satisfaction

✔ Issue type & severity
✔ Concrete evidence & exact locations
✔ Human-interpretable rationale
✔ Trackable source of the flag

Skills (Reading Skill Tags)

Each item in skills represents a confirmed skill supported by evidence in the story.

Field	Description
skill_id	Unique skill identifier from skills.csv
skill_name	Human-readable name (e.g., Character Analysis)
support_level	"strong", "moderate", "weak" from LLM
confidence_raw	Original 0–1 LLM confidence
confidence	Hybrid score (0–1) combining LLM + embedding similarity
similarity_score	Cosine similarity between story and skill embeddings
evidence_text	Substring supporting skill usage
justification	Brief description of why this skill applies
Requirement Satisfaction

✔ Skill identifiers
✔ Confidence values
✔ Embedding-grounded similarity score
✔ Justification & evidence location

3.3 Why Two Output Layers?
JSONL (Detailed)

Ideal for:
automation
dashboards
future ML/LLM retraining
large-scale QA
Each story stored independently → streaming-friendly
Includes all scores, evidence, spans, and rationale
CSV (Summary)

Optimized for:
content specialists
spreadsheets
sorting by priority
reviewing many stories quickly
Concise but linked to deeper JSON records
Consistent IDs Across Formats

Both formats share:

story_id
skill/flag structure
priority scoring
Makes joining, annotating, and feedback tracking straightforward
